# US003-7 — QR e número da guia

Lista e detalhe utilizam o número recebido da API. O QR é desenhado com o código
de `GET /atendimentos/{id}/qrcode`, sem gerar códigos alternativos no frontend.
Sessões incompletas, procedimentos realizados/faturados e guias expiradas não
oferecem QR. A autorização definitiva continua sendo do backend: respostas de
erro ou sem código nunca oferecem imagem, ampliação ou download.

## Teste local integrado

Depende do backend com US003-5 e US003-6. Enquanto a autenticação US000-16 não
estiver integrada, utilize exclusivamente em desenvolvimento os perfis
`dev,qrconsulta-mock,guias-mock`, com um banco descartável para os seeds.

```sh
npm ci
VITE_API_URL=http://localhost:8080 VITE_FONTE_GUIAS=api VITE_AUTH_MOCK_GUIAS=true npm run dev -- --host localhost --port 5173 --strictPort
```

Abra `http://localhost:5173/login?voltar=/beneficiario/minhas-guias`.
CPF fictício: `00000000351`; senha local: `fusex123`.
O login é simulado, mas as guias e o código vêm da API real pelo filtro local
`X-Mock-Login`. Essa opção não funciona em builds de produção e não substitui a
autenticação real. Mantenha `VITE_AUTH_MOCK_GUIAS=false` no uso normal.

Na guia `2026-000003`, apenas o procedimento 4 libera QR. Confira o título,
amplie a imagem e baixe o PNG. Os demais procedimentos não devem oferecer QR.

## Verificação automatizada

Com o backend e os seeds acima rodando, e a porta 5173 livre:

```sh
npx playwright install chrome
npm run build
npm run test:e2e
```

Os testes usam Chrome instalado (`channel: 'chrome'`); alternativamente, instale
Chrome com `npx playwright install chrome`. O servidor frontend de teste é
iniciado e encerrado automaticamente. Há um cenário integrado real e cenários
de resposta 403, 409 e corpo sem código, interceptados apenas no navegador.

Por padrão, lista e QR usam a API. `VITE_FONTE_GUIAS=mock` habilita explicitamente
a demonstração offline, sem fallback automático quando a API falha.
